# keyaki 組織発展計画

keyaki を「AI が実際に業務を担う組織」として構築する。この組織自体が Scaffold プランの実証例であり、検証済みのアーキテクチャをそのまま顧客に提供する。

---

## 組織コンセプト

- **山下（社長）**: 意思決定・方針策定・最終承認
- **AI エージェント群**: 各業務を担う「社員」として機能
- **That's Source 方針**: 外部 SaaS に頼らず、サーバー上で完結させる

Scaffold プランの差別化ポイントである「組織として動く AI」を、自社で先行実装・検証する。

---

## エージェント構成（設計中）

```
~/keyaki/
└── agents/
    ├── kawakami/        # 川上 — エンジニアリング担当（Claude Code）
    │   └── AGENTS.md
    ├── keiri/           # 経理担当（ローカルLLM）
    │   └── AGENTS.md
    └── （今後追加）
```

各エージェントはディレクトリ単位で分離し、それぞれの `AGENTS.md` に役割・行動指針を定義する。

### モデル使い分け方針

| エージェント | モデル | 用途 |
|---|---|---|
| 川上（メイン） | Claude Code | 複雑な判断・コーディング・新規設計 |
| 経理・ルーティン系 | ローカルLLM（Ollama） | 集計・レポート生成・定型処理 |

ローカルLLM は Ollama をサーバー上に構築。モデルは Qwen2.5-7B 等を想定。コスト削減と Scaffold テンプレートの再現性を両立する。

---

## 階層構造（検討中）

山下を社長とし、その下に複数のエージェントが動く組織モデル。オーケストレーター（管理職層）の必要性は認識済みだが、誰が担うかは未定。

```
山下（社長）
  └── オーケストレーター（検討中）
        ├── 川上（エンジニア）
        ├── 経理担当
        └── （マーケ・ライター等、将来）
```

川上がオーケストレーターを兼務するか、専用エージェントを立てるかは、業務量と複雑度を見ながら判断する。

## 積み残し・今後の検討事項

- オーケストレーターの役割と担当エージェントの決定
- エージェント間の連携方式（A: 川上がオーケストレーター として呼び出す / B: 各エージェントが独立 tick で動く）
- ローカルLLM のセットアップタイミングとスペック要件
- 経理担当エージェントの AGENTS.md 定義
- Scaffold テンプレートとしての汎用化（どこまで共通化できるか）
- 将来的な法人化に伴う組織・経理構成の変更対応
