ワークディレクトリ同期（git）

git commitローカルの変更を記録
git pushサーバーへ戻す（cron が毎時取り込み）

repo: keyaki-dev/keyaki-org-workdir（サーバー ~ を private 管理）
ローカル clone: ~/Documents/repos/keyaki/keyaki-org-workdir/

サーバーは cron 毎時で自動 commit+push。同一行が衝突したら自動解決せず ~/org-autocommit.log に記録 → 手動解決。

※ 旧 make pull/push（rsync ミラー server-share/）は補助手段に降格・将来廃止予定。

Initial Setup

初回セットアップ

1

VM 上でセットアップスクリプトを実行

bash scripts/setup.sh — Node.js・claude CLI・gh・gcloud・gws をインストール。ペルソナディレクトリ（kawakami/ chiba/ ishikawa/ sato/）を初期化。

2

Claude・GitHub・GCP を認証する

claude auth login でサブスク認証。gh auth login で keyaki-dev アカウントを登録（reatex 用に rtx-yamashita も登録）。

3

AI組織の脳をデプロイする（ローカルから）

make deploy-agent — 各ペルソナの CLAUDE.md・AGENTS.md と _shared/ をサーバーへ転送（DOCS.md は初回 setup.sh で seed 済み）。

4

skills をデプロイする

make deploy — blog スキル等を ~/.claude/skills/ へ転送。

5

川上に接続して動作確認

make cli — tmux セッションに接続。川上が DOCS.md を読んで文脈を把握し待機状態になれば完了。

Roadmap

自律化ロードマップ

1

Phase 1 — SSH 直接セッション 現在

  • make cli → SSH → claude 対話。DOCS.md でセッション間の記憶を引き継ぎ
  • PC を閉じても VM 上の tmux セッションは動き続ける
  • tick は各セッション内で /schedule / /loop を手動設定
2

Phase 2 — 起動・tick の自動化 次のステップ

  • 起動スクリプトが tmux + claude を自動起動し tick を登録
  • VM 再起動後もセッションが自動復旧する
  • 千葉が inbox 確認・done 集約・Slack 報告を定期自走
3

Phase 3 — 完全自律稼働 将来

  • systemd で全ペルソナのセッションを管理。介入なしで自律稼働
  • Slack を受信口に、必要時のみ山下が介入する形態
  • 佐藤をローカル LLM に移行（コスト最適化）
